# 第一部分 · 使用

## 1.1 安装与启动

### 1.1.1 环境依赖

| 项目 | 要求 |
|---|---|
| 操作系统 | macOS 11（Big Sur）或更高版本 |
| 处理器 | Intel 与 Apple 芯片均可（通用二进制） |
| 磁盘占用 | 约 1.2 MB |
| 运行时依赖 | 无。不需要安装 Python、Node 或任何第三方库 |

**关于隐私与资源占用**：

- **完全离线**。应用内没有任何网络请求代码，不会连接服务器，也不会检查更新。
- **不上传任何数据**。不读取你的文档、照片、剪贴板或输入内容。
- **不消耗 token，无 API 调用**。所有行为由本地状态机决定，与任何大模型服务无关。
- **只有一个后台进程**，空闲时每秒执行一次计时器（用于提醒与状态计时），
  没有定时轮询磁盘或网络的行为。
- 偏好设置保存在 `~/Library/Preferences/com.popohere.pet.plist`，
  待办清单保存在 `~/Library/Application Support/PopoHere/checklist.json`。
  删除应用后这两个文件可一并手动删除。

### 1.1.2 安装步骤

1. 打开仓库的 **Releases** 页面，下载最新的 `PopoHere-<版本>.zip`。
2. 解压得到 `PopoHere-<版本>` 文件夹，里面有 `PopoHere.app`、`启动 PopoHere.command`
   和一份说明。
3. 把 `PopoHere.app` 拖进「应用程序」文件夹（也可以就地运行，但拖进去更便于日后查找）。
4. 双击 `PopoHere.app`。

启动后：

- 屏幕**右上角菜单栏**会出现一个小猫剪影图标；
- 桌宠出现在屏幕**左下角**；
- 应用**不会出现在 Dock**，也不会抢占当前窗口的焦点。

> 如果双击后没有任何反应，先看下一节的系统提示。

### 1.1.3 系统提示

首次打开时，macOS 可能弹出这样的提示：

> "PopoHere" 无法打开，因为来 Apple 无法验证 "PopoHere" 是否包含可能危害 Mac 安全或隐私的恶意软件。

**原因**：本应用未购买苹果开发者证书，只做了本地临时签名（ad-hoc）。
macOS 会对所有未经公证的应用给出这条统一提示，它与应用本身的行为无关。

**解决办法（任选其一，只需一次）**：

| 方法 | 操作 |
|---|---|
| 右键打开（推荐） | 在 Finder 中**右键**（或按住 Control 点击）`PopoHere.app` → 选「打开」→ 在弹窗中再点一次「打开」 |
| 系统设置 | 双击被拦截后，打开「系统设置 → 隐私与安全性」，在页面下方点「仍要打开」 |
| 终端命令 | `xattr -dr com.apple.quarantine /Applications/PopoHere.app` |

成功打开一次之后，系统会记住这个决定，之后可以正常双击启动。

> 压缩包内附带 `启动 PopoHere.command`，它会自动清除该标记后启动应用。
> 该脚本首次运行时同样可能被拦截，处理方式与上面一致。

## 1.2 互动介绍

桌宠的行为由本地状态机驱动，会根据你的操作和时间流逝自行切换状态。
下表中的「鼠标」指使用外接鼠标，「触摸板」指使用 Mac 自带触控板。

| 你想做的事 | 鼠标操作 | 触摸板操作 | 桌宠的反应 |
|---|---|---|---|
| 抚摸它 | 在它身上**单击** | 单指**轻点**一下 | 进入「被抚摸」状态 |
| 逗它发火 | 快速**连续点击 10 次** | 单指**快速连续轻点 10 次** | 第 10 下当场翻脸，进入「不耐烦」状态 |
| 把它抱走 | **按住拖动** | 单指**按住并拖动** | 被拎起，跟随光标移动；松手后落地 |
| 叫醒它 | 它在睡觉时点一下 | 轻点一下 | 先「惊醒」，再回到静息 |
| 什么都不做 | — | — | 静置 5 秒后，它自己去玩或趴下睡觉 |
| 打开菜单 | **右键**点击它 | 单指**双指轻点**（即右键） | 弹出菜单 |
| 打开菜单（另一种方式） | 点**菜单栏**的小猫图标 | 同上 | 弹出系统菜单 |

几点说明：

- **单击与拖拽的区分**：位移小于 12 px 且按住时间短于 300 ms 才计为单击，
  否则视为拖拽。这个阈值同时作用于触摸板，正常的轻点不会被误判成拖动。
- **抚摸计数**：连续两次抚摸的间隔不超过 4 秒才会累计；停下超过 4 秒计数归零。
  达到 10 次翻脸后进入 6 秒冷却，冷却期内继续点击不会再触发。
- **状态面板底部**会实时显示「连撸 N/10」，可以据此判断距离翻脸还有几次。
- **静息分流**：静置 5 秒后，35% 的概率去「自娱自乐」，65% 的概率去「睡觉」。
  这是按猫的习性设定的，如果用于其它类型的桌宠，可在 `theme.json` 中调整。
- **位置与大小会被记住**，下次启动回到上次的位置。

## 1.3 功能介绍

菜单有两种打开方式，内容完全一致、状态互相同步：

- **右键桌宠**：在光标处弹出玻璃面板；
- **菜单栏图标**：在屏幕顶部弹出系统菜单。

下文统一按「进入 → 按键 → 设置 → 效果 → 默认值 → 其他」的顺序说明。

### 1.3.1 定时提醒

**如何进入**
右键桌宠 → 「定时提醒」；或菜单栏图标 → 「定时提醒」。若菜单已经打开，直接点该条目。

**按键介绍**

| 位置 | 元素 | 作用 |
|---|---|---|
| 每行最左 | 圆形开关 | 该条提醒的总开关 |
| 中间 | `−` / `分钟数` / `＋` | 调整提醒间隔 |
| 每行最右 | `一次` / `间隔` | 提醒方式：响一次即结束，或按间隔循环 |

**如何设置**

1. 点 `＋` / `−` 把间隔调到需要的值。取值按合法档位递增：**1 → 5 → 10 → 15 → 20 …**，
   最大 180 分钟；递减时 5 之后直接回到 1。
2. 选择提醒方式：`一次`（默认）或 `间隔`。
3. 打开最左侧的总开关。

**对应效果**

到点后，屏幕**右上角**弹出一个独立面板：

```
摸鱼结束，接着干活~（7s）
         [ 确认 ]
```

- 点「确认」立即关闭；
- 不理会时，括号内的倒计时归零（10 秒）后自动关闭；
- 一条提醒结束即代表「这一轮结束」：`一次` 模式下该条会自动关闭总开关，
  `间隔` 模式下则重新开始计时，直到你手动关闭；
- 多条提醒同时到点时会**叠在同一个面板里**，各自倒计时、各自确认，先关哪条由你决定。

**默认取值**

| 条目 | 间隔 | 到点文案 | 开关 | 模式 |
|---|---|---|---|---|
| 摸鱼 | 25 分钟 | 摸鱼结束，接着干活~ | 关 | 一次 |
| 喝水 | 45 分钟 | 到时间了，请去喝口水！ | 关 | 一次 |
| 久坐拉伸 | 60 分钟 | 到时间了，请去拉伸一下！ | 关 | 一次 |

**其他说明**

- 提醒**不依赖桌宠**：即使把桌宠隐藏，弹窗仍会照常出现，也不依赖声音或动画。
- 弹窗不会抢占键盘焦点，你在其它应用中打字不会被打断；鼠标点「确认」一次即可生效。
- 应用退出后提醒停止；重新打开时按保存的间隔重新计时。

### 1.3.2 待办清单

**如何进入**
右键桌宠 → 「待办清单」；或菜单栏图标 → 「待办清单」。

**按键介绍**

| 元素 | 作用 |
|---|---|
| 圆形勾选框 | 标记完成 / 取消完成 |
| 条目文字（单击） | 编辑该条内容 |
| 底部「＋ 添加」 | 新增一条 |
| 底部「清空」 | 删除全部条目，需二次确认 |

**如何设置**

1. 点「＋ 添加」，输入内容后回车；
2. 点条目文字可直接修改，再次回车保存；
3. 完成的条目点勾选框标记，勾选后文字显示为删除线。

**对应效果**

- 条目立即写入本地文件，关闭应用后不会丢失；
- 全部条目都勾选完成时，桌宠会做出一次庆祝反应。

**默认取值**

- 最多 **10 条**，每条最多 **50 个中文字**（超出部分会被截断）；
- 初始为空。

**其他说明**

- 待办清单与提醒相互独立，互不影响；
- 数据保存在 `~/Library/Application Support/PopoHere/checklist.json`，可直接备份或迁移。

### 1.3.3 显示 / 隐藏桌宠

**如何进入**
右键桌宠 → 「显示 / 隐藏桌宠」；或菜单栏图标 → 同名条目。

**按键介绍**
该条目是一个切换项，点击一次切换一次状态。

**如何设置**
无需设置。

**对应效果**

- 隐藏后桌宠从桌面消失，但**应用仍在运行**，菜单栏图标仍在；
- 再次点击即可恢复显示，位置保持隐藏前的位置。

**默认取值**
启动时显示桌宠。

**其他说明**

- **隐藏不等于退出**。需要彻底结束请使用「退出」。
- 隐藏桌宠时，右键菜单与状态面板会一并收起；定时提醒仍然有效。

### 1.3.4 显示 / 隐藏桌宠状态

**如何进入**
右键桌宠 → 「显示 / 隐藏桌宠状态」；或菜单栏图标 → 同名条目。

**按键介绍**
状态面板是屏幕右下角的一块常驻浮窗，包含三部分：

| 区域 | 作用 |
|---|---|
| 标题栏右侧「✕」 | 关闭状态面板 |
| 状态列表 | 点击任一状态名，立即预览该状态的贴图与动效 |
| 底部信息栏 | 显示当前状态、连撸计数、已停留时长 |

**如何设置**

- 点击状态名即可预览，预览只播放一次，结束后回到「菜单」或「静息」；
- 按住标题栏可拖动面板到任意位置；
- 面板尺寸随内容变化，位置会自动保持在屏幕内。

**对应效果**

- 预览过程中不会写入连撸计数，也不会触发翻脸；
- 若右键菜单处于打开状态，预览结束后桌宠回到「菜单待命」，而不是直接进入静息。

**默认取值**
启动时**不自动打开**，需要手动开启。开启状态会被记住，下次启动不恢复。

**其他说明**

- 状态面板从属于桌宠：隐藏桌宠时它一并收起，隐藏期间该菜单项为灰色不可选；
- 重新显示桌宠后，如果此前是开启状态，会按记录恢复。

### 1.3.5 调整大小

**如何进入**
右键桌宠 → 「大小」；或菜单栏图标 → 「大小」。展开后出现四个档位。

**按键介绍**
`160 px` / `220 px` / `300 px` / `380 px`，当前档位前有勾选标记。

**如何设置**
点击任一档位即时生效。

**对应效果**
桌宠贴图等比缩放，命中区域同步缩放，菜单与提醒不受影响。

**默认取值**
`220 px`。

**其他说明**
所选档位会写入偏好设置，下次启动沿用。

### 1.3.6 开机自启

**如何进入**
右键桌宠 → 「开机自启」；或菜单栏图标 → 同名条目。

**按键介绍**
切换项，条目右侧显示勾选状态。

**如何设置**
点击一次即可开启或关闭。

**对应效果**
开启后会在 `~/Library/LaunchAgents/` 写入一个启动项，登录时自动运行 PopoHere；
关闭时移除该项。

**默认取值**
关闭。

**其他说明**
若手动删除了应用，建议先把该开关关闭，避免残留启动项指向不存在的路径。

### 1.3.7 声音

**如何进入**
右键桌宠 → 「声音」；或菜单栏图标 → 「声音」。

**按键介绍**
`开` / `关` 两个选项。

**对应状态**
当前版本**没有附带音频素材**，因此整个「声音」条目为**灰色不可选**。
这是预期行为，不是故障。

**其他说明**
如果自行准备了音频素材并接入，该条目会在检测到素材后自动可用。

### 1.3.8 打开素材文件夹 / 重置位置

**打开素材文件夹**
在 Finder 中打开应用包内的素材目录，便于查看当前使用的贴图。
该操作只读，不会修改任何文件。

**重置位置**
把桌宠移回默认位置（屏幕左下角）。当桌宠被拖到屏幕外或被其他窗口长期遮挡时使用。

### 1.3.9 关于与退出

**关于 PopoHere**
点击后在浏览器中打开项目主页，可查看更新日志、提交问题或参与改进。

**退出**
结束进程。退出前会保存当前位置与偏好设置。

> 注意：菜单栏图标被其它图标挤压时可能不易找到，可按住 `⌘` 拖动图标调整顺序。

## 1.4 常见问题

**桌宠不见了？**
先看菜单栏图标是否存在。若「显示 / 隐藏桌宠」处于隐藏状态，点一次即可恢复。
也可以使用「重置位置」，把桌宠移回屏幕左下角。

**为什么第一次打开被系统拦截？**
因为未购买苹果开发者证书，详见 [1.1.3 系统提示](#113-系统提示)。

**它会联网吗？会上传我的东西吗？**
不会。应用内没有网络请求代码，也不读取你的个人文件。

**能用在 Windows 或 Linux 上吗？**
不能。当前版本是 macOS 原生外壳（AppKit + WKWebView），依赖 macOS 专有接口。

**为什么每次进入同一个状态，姿势不太一样？**
同一状态准备了多张贴图时会随机抽取一张并锁定，离开再进入才重新抽取。
这让桌宠不至于长时间保持同一个姿势。

**点了没反应？**
先确认是否点在了桌宠身上，而不是它周围透明的区域。
另外，快速连点时第 10 下会进入「不耐烦」，此时继续点击不会再有反应，属正常设计。

**连点很多下却不翻脸？**
两次点击的间隔超过 4 秒会重新计数。状态面板底部的「连撸 N/10」可以看到当前计数。

**提醒响了但我没看到？**
弹窗固定在屏幕右上角，且会在 10 秒后自动关闭。
若在此期间处于全屏应用中，弹窗会显示在对应空间内；建议先退出全屏再确认一次。

**桌宠的照片会进仓库吗？**
仓库中只包含**每个状态第一张**原始照片作为示例，用于说明素材的组织方式；
其余素材与处理后贴图之外的中间产物都在本地维护。

# 第二部分 · 自己做一只

本项目的架构、代码与素材处理流程完全开放。你可以：

- 直接使用现有代码 + 自己准备的素材，做出**属于你的桌宠**（不需要写代码）；
- 或者基于现有代码做**二次开发**，增加新的状态、功能模块或交互方式。

下面按「准备素材 → 准备环境 → 跑预处理 → 重新构建」的顺序说明，
最后附上架构介绍，便于深入修改。

## 2.1 制作步骤

### 2.1.1 准备素材

素材放在 `source/` 目录下：

```
source/
├── origin_images/     原始照片（桌宠贴图的来源）
└── origin_audios/     原始音频（可为空）
```

**命名规则**

```
<状态>_<序号>.png
```

- 序号从 1 开始，同一状态有几张就编到几号；
- 只有一张时可以省略序号（`idle.png`），但建议统一带序号，日后加图不必改名；
- 支持 PNG / JPG；背景会被预处理自动抠除。

**需要哪些状态**

| 状态 | 含义 | 建议张数 |
|---|---|---|
| `idle` | 静息 | 3–4 |
| `touch` | 被抚摸 | 4–6 |
| `scratch` | 不耐烦 | 2–3 |
| `play` | 自娱自乐 | 4–6 |
| `sleep` | 睡觉 | 3–4 |
| `dragging` | 被拎起 | 2 |
| `menu` | 端正坐好（菜单打开时） | 1–2 |
| `startled` | 惊醒 | 1–2 |
| `landed` | 落地 | 1–2 |

另外有两个非状态素材：

| 用途 | 文件名 | 说明 |
|---|---|---|
| 应用图标 / 面板标识 | `logo_1.png` | 建议使用正脸或轮廓清晰的图 |
| 菜单栏图标 | `menubar_1.png` | 任意姿态均可，预处理会按 alpha 通道生成纯黑剪影 |

**拍摄建议**

**① 背景尽量使用纯色。**
预处理使用 rembg（u2net）做语义分割，它擅长「单一主体 + 干净背景」的画面。
白墙、纯色地板、纯色沙发套是最理想的背景；花纹墙纸、堆满杂物的房间、
画面中出现其他宠物或人时，容易产生毛边或残留，且没有重试机制。

**② 保持同一机位与同一套灯光。**
不同状态之间切换时，主体的体型与地面线需要能对上，否则会出现明显的跳动。

**③ 同一状态的多张图，只改变表情与姿态，不要移动位置。**

**④ 照片方向即最终显示方向，程序不会替你旋转。**
预处理只做三件事：去背景、裁到主体外框、缩放对齐；不会旋转或翻转。
因此如果照片在 Finder 中看起来是横着的，桌面上也会是横着的，请先在图片工具中校正。

**⑤ 主体在画面中的占比尽量一致。**
同一状态的多张图会按视觉面积做一次对齐（只缩小不放大），
但源自不同焦段的照片仍可能有明显差异。

## 2.2 架构介绍

### 一句话概括

> 一个 Objective-C 的透明浮窗，里面嵌入一个 WebView；
> 桌宠的全部行为由网页中的 JavaScript 状态机驱动。

```
┌─────────────────────────────────────────────┐
│  PopoHere.app                               │
│  ┌───────────────────────────────────────┐  │
│  │ func_window  (Objective-C)            │  │
│  │  · 无边框透明 NSWindow，置顶、不进 Dock │  │
│  │  · 菜单栏 NSStatusItem                │  │
│  │  · 拖拽：NSEvent 本地监视器 → 屏幕坐标  │  │
│  │  · 位置 / 大小 / 视图 → NSUserDefaults  │  │
│  │  ┌─────────────────────────────────┐  │  │
│  │  │ WKWebView                       │  │  │
│  │  │  func_state   状态机（纯逻辑）    │  │  │
│  │  │  func_render  状态 → 贴图/动效    │  │  │
│  │  │  func_input   命中判定/单击拖拽    │  │  │
│  │  │  func_menu    菜单桥 + 面板页面    │  │  │
│  │  │  main         装配 + 主循环       │  │  │
│  │  └─────────────────────────────────┘  │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

### 技术选型

外壳使用 `clang + Objective-C + WebKit`：无需第三方依赖、产物约 1.2 MB、
启动在半秒以内，并且可以直接复用 Web 技术做界面。
把交互逻辑留在 JavaScript 中还有一个实际好处：修改行为不必重新编译原生外壳，
`build_web.py` 十毫秒内即可完成构建，浏览器中可以直接看到效果。

### 各模块职责

| 模块 | 位置 | 职责 | 边界 |
|---|---|---|---|
| `func_state` | `code/core/func_state/` | 状态流转、按概率选择视觉、单击与拖拽的语义 | 不接触 DOM，不读全局变量 |
| `func_render` | `code/core/func_render/` | 状态 → 贴图 / 动效 / 气泡 | 不修改状态，不处理鼠标 |
| `func_input` | `code/core/func_input/` | 命中区域、单击与拖拽的区分 | 不决定进入哪个状态 |
| `func_menu` | `code/core/func_menu/` | 右键菜单桥接、面板页面（`panel.html`） | 不管理窗口 |
| `main` | `code/core/main.js` | 装配、主循环、尺寸与位置、对外接口 | 不承载业务逻辑 |
| `func_window` | `code/core/func_window/` | 窗口、菜单栏、拖拽跟踪、持久化、脚本桥 | 不管理桌宠状态 |
| `func_reminder` | `code/core/func_reminder/` | 提醒计时（`PHReminder`）与到点弹窗（`PHAlert`） | 不处理界面细节 |
| `func_checklist` | `code/core/func_checklist/` | 待办清单的存储 | 不渲染界面 |

状态机不引用任何 DOM API，因此可以直接用 Node 运行单元测试。
这条边界建议保持：它是唯一能脱离图形界面做回归测试的地方。

### 数据流

```
theme.json ──┐
             ├─→ build_web.py ─→ 内联成单个 index.html ─→ WKWebView
pet_images ──┘                      (图片转 base64 webp)

用户操作 ─→ func_input ─→ PetStateMachine ─→ func_render ─→ DOM
                │                 ↑
                └── 原生模式 ──→ func_window（以屏幕坐标移动窗口）
```

### 拖拽：一个必须注意的坐标系问题

**症状**：拖动时画面剧烈抖动，光标与桌宠之间有延迟。

**根因**：如果 JavaScript 使用 `e.clientX` 计算位移，再让原生窗口跟随移动，
就会形成坐标反馈环——`clientX` 是相对网页视口的坐标，而移动的正是承载该视口的窗口：

```
鼠标右移 10px → 窗口右移 10px → 鼠标相对视口退回 10px → 位移归零 → 窗口被拉回 → 循环
```

**现行做法**：

1. **窗口位移全部由原生层完成**。收到按下事件后安装 `NSEvent` 本地监视器，
   用 `[NSEvent mouseLocation]`（屏幕坐标）在事件到场的同一时刻调用 `setFrameOrigin`，
   与拖动窗口标题栏使用同一套机制，无跨进程往返。
2. **页面侧同样使用 `e.screenX / e.screenY` 判定**。这一步是必需的：
   位移交给原生层后，若页面仍用 `clientX` 判断阈值，位移会长期接近于 0，
   状态机无法进入拖拽状态，松手还会被误判为单击。
3. **原生模式下页面不发送任何位移消息**，只发送 `press` / `release` 两个事件。

**回归测试**：`code/test/drag_tracking_test.py` 专门构造「`clientX` 不变、
只有 `screenX` 递增」的场景，覆盖上述约束。

### theme.json：状态与贴图的契约

```jsonc
{
  "behavior": {                    // 全局行为参数
    "idle_duration_sec": 5,        // 静息多久后开始自然流转
    "idle_to_play_probability": 0.35, // 去自娱自乐的概率，其余去睡觉
    "touch_repeat_window_sec": 4,  // 连续抚摸的计数窗口
    "touch_scratch_threshold": 10, // 达到该次数转入不耐烦
    "scratch_cooldown_sec": 6,     // 不耐烦结束后的冷却时间
    "click_max_drift_px": 12,      // 位移小于它视为单击
    "click_max_duration_ms": 300,  // 时长小于它视为单击
    "menu_timeout_sec": 120,       // 菜单未关闭时的兜底
    "preview_duration_sec": 6      // 状态预览的时长
  },
  "states": {
    "idle": {
      "visuals": ["idle_1.png", "idle_2.png"],  // 进入时等概率抽取并锁定
      "loop": true,
      "duration": 1.5,             // 非循环状态的停留秒数
      "motion": "breathe",         // none / breathe / breathe-slow / bob-walk / shake / float / drop
      "bubble": "💤"               // 可选，气泡文案
    }
  },
  "hitBoxes": {
    "body": { "x": 0.06, "y": 0.04, "w": 0.88, "h": 0.92 }  // 相对比例，原点在左上角
  }
}
```

`motion` 用 CSS 动画为静态贴图补充生命感，从而省去逐帧素材；
`bubble` 使用文字或 emoji 而非图片，也是出于同样的成本考虑。
这两个字段都可以按桌宠类型调整：例如用于爬行动物时，可把呼吸动效调慢、去掉气泡。

```

        │  code/prepare/cutout.py        去背景 + 归一化（约 1 秒/张）
        ▼
code/pet_images/*.png  +  theme.json    状态与贴图的契约
```
