# PopoHere 产品需求文档 v2.0

**项目名称**：PopoHere
**版本**：v2.0（待确认稿）
**最后更新**：2026-10-30
**状态**：⏳ **待用户确认**。确认后才会进入开发。
**上一版本**：[PRD_v1.0_archive.md](PRD_v1.0_archive.md)

## 0. 这一版要解决什么

v1.0 已经能跑：一只透明浮窗里的猫，会呼吸、溜达、睡觉、被摸、炸毛、被抱起。但它有两个结构性问题：

1. **状态划分太碎，而每个状态只有一张图。** 10 个状态、10 张图，摸头/摸脚/挠人三张还是同一个文件。结果是"状态很多，但看起来都一样"。
2. **没有功能菜单。** 只有一个四条目的临时右键菜单，桌宠除了可爱之外不提供任何实用价值。

v2.0 的方向是反过来的：**状态收窄、每个状态喂饱素材**，再加一套真正的菜单系统，让桌宠从"会动的摆件"变成"桌面上一个能干活的东西"。

## 1. v1.0 实际交付 vs 原 PRD 的差异

这一节是给评审用的：先说清楚上一版偏离了原设计哪些地方，免得 v2.0 建立在错误的假设上。

### 1.1 被推翻的决定

| 项 | 原 PRD（v1.0） | 实际实现 | 原因 |
|---|---|---|---|
| **技术栈** | Python 3.11 + PySide6 | **Objective-C (AppKit) + WKWebView** | PySide6 在本机装不上（环境拦截 pip 大依赖树，镜像也不行）；Swift 工具链也不可用。`clang + Objective-C + WebKit` 是当场唯一能编译、零依赖的方案 |
| **打包** | `pyside6-deploy` / PyInstaller | `clang` 直接产出通用二进制 `.app` | 没有 Python 运行时，包体从预计 50–85MB 降到 **768KB**，启动 <0.5s |
| **配置存储** | `theme.json` + `config.json` | `theme.json` + **NSUserDefaults** | macOS 原生偏好存储，不需要自建文件 |
| **动画** | `QTimer` 驱动 `QPixmap` 帧切换 | CSS 动画（`motion` 字段） | 每状态只有 1 张图，帧切换无从谈起；改用轻微形变给静态图生命感 |
| **气泡** | PNG 素材（`bubble_zzz.png`…） | **emoji 字符串** | 省掉一整套气泡素材，且可随时改文案 |

### 1.2 实现时才发现的偏差

| 项 | 原 PRD | 实际 | 说明 |
|---|---|---|---|
| **hitBox 坐标原点** | 左下角（`y` 从底部算） | **左上角** | 实现走 DOM 坐标，左上更直观。PRD 里的示例值因此全部不适用，实际值也不同（`head y=0.02` / `paw y=0.52`） |
| **新增字段 `motion`** | 无 | `none/breathe/breathe-slow/bob-walk/shake/float/drop` | 用 CSS keyframes 表达呼吸、走动晃动、受惊抖动、落地回弹 |
| **拖拽实现** | Qt 窗口跟随鼠标 | `NSEvent` 本地监视器 + 屏幕坐标同步 | 用 `clientX` + 逐帧 `postMessage` 会形成坐标反馈环，导致剧烈抖动。这是 v1.0 修的最后一个大 bug |
| **菜单栏** | 显示/隐藏、暂停、打开主题、退出 | 多加了**大小分档**（160/220/300/380） | 尺寸调节是高频需求 |
| **右键菜单** | 功能菜单（进入 `menu` 状态） | 只有 5 条临时项 | v2.0 才正式做 |
| **`sleep` 计时** | 窗口内按下/拖拽重置 | 状态机 `idle` 计时满 5s 分流 | 任何状态变化都会重置 `elapsed`，效果等价 |

### 1.3 完成度盘点

| 原 PRD 要求 | 状态 |
|---|---|
| 9 必需状态 + `landed` 可选 | ✅ 10 个全部实现 |
| 单击 <5px / <300ms、拖拽 ≥5px 判定 | ✅ |
| `startled` 仅在 `sleep` 被唤醒时触发 | ✅ 并有回归测试 |
| `menu` 状态 2 秒兜底 | ✅ |
| `pet_paw` → `scratch` 概率 + 冷却 + 连续摸脚 | ✅ 并修掉"第一次摸脚就自触发"的 bug |
| 空白区不作响应，仅留钩子 | ✅ `onBlankClick` |
| 素材经 `theme.json` 解耦 | ✅（但素材本身重复，见下） |
| 完全无声、无音频库 | ✅ |
| 不做全局鼠标监听 | ✅ |
| Gatekeeper 说明 + 免公证分发 | ✅ README/使用说明都写了 |
| **小游戏预留** | ✅ 空钩子 |
| **多帧素材** | ❌ 每状态仅 1 张，源文件还有 3 组重复 |

## 2. v2.0 设计原则

1. **状态宁少勿多，素材宁多勿少。** 10 个状态各 1 张，不如 7 个状态各 4 张。
2. **一个状态 = 一种情绪，不是一个动作部位。** 摸头和摸脚对猫来说都是"被撸"，合并。
3. **转换要有因果，不能纯随机。** 静息→睡觉/自己玩是概率；连着摸了三次→生气必须是被摸出来的。
4. **素材命名即契约。** 用户只按 `<状态>_<序号>.png` 丢图，不写 JSON。
5. **功能模块插件化。** 每个功能一个 `func_xxx`，加功能不改核心。

## 3. 状态机 v2.0

### 3.1 状态总表（7 个常规 + 2 个过渡）

| # | 状态 ID | 中文名 | 类型 | 时长 | 动效 | 气泡 |
|---|---|---|---|---|---|---|
| 1 | `idle` | 静息 | 常规 | 持续 | `breathe` | — |
| 2 | `pet_touch` | 互动 | 常规 | 1.5s | `none` | 随机 `❤️`/`😌`/`✨` |
| 3 | `scratch` | 挠人 | 常规 | 1.5s | `shake` | `💢` |
| 4 | `play` | 自娱自乐 | 常规 | 2.5s | `bob-walk` | — |
| 5 | `sleep` | 睡觉 | 常规 | 持续 | `breathe-slow` | `💤` |
| 6 | `dragging` | 被抱起 | 模态 | 持续 | `none` | — |
| 7 | `menu` | 待命（菜单中） | 模态 | 菜单关闭 | `none` | — |
| 8 | `startled` | 惊醒 | 过渡 | 1.0s | `shake` | `❗` |
| 9 | `landed` | 落地 | 过渡 | 0.8s | `drop` | — |

**相对 v1.0 的变化**

| v1.0 | v2.0 | 说明 |
|---|---|---|
| `pet_head` + `pet_paw` | → **`pet_touch`** | 两个状态合并为一个"被撸"状态 |
| `walk` | → **`play`** | 语义从"走动"扩大到"自己找事做"（走路/舔毛/伸懒腰/追尾巴都由素材表达） |
| `startled` / `landed` / `dragging` / `menu` / `idle` / `sleep` / `scratch` | 保留 | — |

净效果：**10 → 7 个常规状态**，同时每个状态可容纳多张素材。

### 3.2 交互简化

v1.0 用 `head` / `paw` 两个 hitbox 区分摸头摸脚。v2.0 **合并为一个 `body` 区域**：

- 整只猫就是一个命中区，点哪儿都是"撸它"
- 具体给出哪种反应，由 `pet_touch` 的素材池随机决定
- hitbox 简化后，躺姿/站姿共用一套也就不再有偏移问题（v1.0 遗留短板 #3 顺手解决）

> 如果以后想让"摸头"和"摸脚"有不同反应，按 `pet_touch_head_1.png` / `pet_touch_paw_1.png` 命名即可扩展，不需要改状态机——这条留作后路，v2.0 不实现。

### 3.3 转换规则

```
                    ┌──────────── 单击 ────────────┐
                    │                              ▼
   ┌────────┐   5s   ┌──────┐                ┌───────────┐
   │  idle  │───────▶│ play │                │ pet_touch │
   └────────┘  35%   └──────┘                └───────────┘
      │  │              │                          │
      │  │ 65%          │ 播完                      │ 连击 3 次
      │  ▼              ▼                          ▼
      │ ┌───────┐    ┌──────┐                ┌─────────┐
      │ │ sleep │    │ idle │                │ scratch │
      │ └───────┘    └──────┘                └─────────┘
      │     │ 点击/拖拽                            │ 播完
      │     ▼                                      ▼
      │ ┌──────────┐                            ┌──────┐
      │ │ startled │                            │ idle │
      │ └──────────┘                            └──────┘
      │     │ 播完
      │     ▼
      │  idle / dragging（手还按着）
      │
      └── 拖拽 ──▶ dragging ── 释放 ──▶ landed ──▶ idle

   任意状态 ── 右键 ──▶ menu ── 关闭/8s 超时 ──▶ idle
```

**完整转换表**

| 当前状态 | 事件 | 目标 | 条件 |
|---|---|---|---|
| `idle` | 停留满 `idle_duration_sec` | `play` | 概率 `idle_to_play_probability`（默认 0.35） |
| `idle` | 同上 | `sleep` | 其余概率（默认 0.65，**睡觉概率更高，符合猫性**） |
| `idle` | 单击 | `pet_touch` | — |
| `idle` | 拖拽 ≥5px | `dragging` | — |
| `pet_touch` | 播完 | `scratch` | `touch_streak ≥ touch_scratch_threshold`（默认 3） |
| `pet_touch` | 播完 | `idle` | 否则 |
| `pet_touch` | 拖拽 | `dragging` | 立刻打断 |
| `scratch` | 播完 | `idle` | 进入冷却 `scratch_cooldown_sec`（默认 6s），`touch_streak` 清零 |
| `play` | 播完 | `idle` | — |
| `play` | 单击 | `idle` | 打断，**不**触发 `pet_touch` |
| `sleep` | 单击 / 拖拽 | `startled` | 唯一入口 |
| `sleep` | 右键 | `menu` | — |
| `startled` | 播完 | `dragging` | 手还按着 |
| `startled` | 播完 | `idle` | 否则 |
| `dragging` | 释放 | `landed` | 有 `landed` 素材 |
| `dragging` | 释放 | `idle` | 无素材 |
| `landed` | 播完 | `idle` | — |
| `menu` | 菜单关闭 / 8s 超时 | `idle` | — |
| 任意 | 右键 | `menu` | `menu` / `dragging` 状态除外 |

**摸人计数（`touch_streak`）的算法**

在**进入** `pet_touch` 的那一刻计算，不在结束时算（v1.0 在这里踩过坑）：

```
if 上次进入 pet_touch 距今 ≤ touch_repeat_window_sec:
    touch_streak += 1
else:
    touch_streak = 1
```

- 冷却期内（`scratch` 结束后 6 秒）`touch_streak` 保持 0，摸它只会 `pet_touch`
- 阈值默认 3：**连着撸三次就翻脸**

这条规则是确定性的，不是概率——用户"一直激活就会生气"的直觉必须可靠复现，不能靠随机。

### 3.4 行为参数（`theme.json → behavior`）

| 参数 | 默认 | 说明 |
|---|---|---|
| `idle_duration_sec` | 5 | 静息多久后自己找事做 |
| `idle_to_play_probability` | 0.35 | 分流去 `play` 的概率，其余去 `sleep` |
| `touch_repeat_window_sec` | 4 | 连击判定窗口 |
| `touch_scratch_threshold` | 3 | 几次连击后翻脸 |
| `scratch_cooldown_sec` | 6 | 挠完多久内不记仇 |
| `click_max_drift_px` | 5 | 位移小于它算单击 |
| `click_max_duration_ms` | 300 | 时长小于它算单击 |
| `menu_timeout_sec` | 8 | 菜单兜底超时（v1.0 是 2s，v2.0 是真菜单，需要更久） |

## 4. 素材规范与清单

### 4.1 命名规则

```
<状态>_<序号>.png     序号从 1 开始，等宽无前导零
```

- 一个状态只有一张时可省略序号（`idle.png`），**但推荐统一带序号**，省得以后加图要改名
- 同一状态的素材在进入状态时**等概率随机抽一张并锁定**，状态持续期间不再变
- 背景随便，预处理会自动抠图
- 建议构图：同一状态的多张图尽量**同一个机位、同一个地面基线**，否则切换时会跳

### 4.2 状态素材清单

| 状态 | 张数 | 拍什么 | 文件名 |
|---|---|---|---|
| `idle` | **3–4** | 坐着/趴着的静态，表情略有差别（发呆、看你、微眯眼） | `idle_1.png` … `idle_4.png` |
| `pet_touch` | **4–6** | 被撸的反应：眯眼享受、抬头蹭手、翻肚皮、尾巴甩、侧头 | `pet_touch_1.png` … `pet_touch_6.png` |
| `scratch` | **2–3** | 不高兴：哈气、抬爪、飞机耳、炸毛 | `scratch_1.png` … `scratch_3.png` |
| `play` | **4–6** | 自己找事：走路、舔毛、伸懒腰、追尾巴、抓空气 | `play_1.png` … `play_6.png` |
| `sleep` | **3–4** | 睡觉：蜷缩、侧躺、露肚皮、爪子盖脸 | `sleep_1.png` … `sleep_4.png` |
| `dragging` | **2** | 被拎起来：四脚悬空、乱蹬 | `dragging_1.png`、`dragging_2.png` |
| `menu` | **1–2** | 端正坐好、看着你（右键菜单弹出时用） | `menu_1.png`、`menu_2.png` |
| `startled` | **1–2** | 惊醒：猛地抬头、飞机耳 | `startled_1.png`、`startled_2.png` |
| `landed` | **1–2** | 落地：四脚着地瞬间、微微下蹲 | `landed_1.png`、`landed_2.png` |

**合计约 21–30 张。** 这是 v2.0 的核心工作量，也是这一版能不能"看起来丰富"的关键。

> 现有的 `cool.png` 我暂时没想好归到哪儿——如果它是"趴着很酷"的姿势，建议并入 `idle`（改名 `idle_5.png`）；如果是别的情绪，请告诉我它对应什么。

### 4.3 其他素材（**需要补充**）

| 用途 | 张数 | 建议文件名 | 规格 |
|---|---|---|---|
| **应用图标 / 菜单面板顶部 logo** | 1 | `logo_1.png` | 正方形，透明背景，512×512 或更大，主体占画面 70–85% |
| **菜单栏图标剪影** | 1 | `menubar_1.png` | **纯黑 + 透明**，正方形，建议 88×88（会缩到 22pt 显示）。macOS 会把它当 template image 自动适配深/浅色菜单栏，所以**不要带颜色和阴影** |

> 这两个命名与状态素材同一套规则（`<名字>_<序号>`），只是名字不是状态名。
> **缺失时的降级方案**：`menubar_1.png` 缺失 → 自动从 `menu_1.png` 抠出剪影；`logo_1.png` 缺失 → 菜单面板顶部只显示文字 "PopoHere"。

### 4.4 音频素材（v2.0 预留，可为空）

目录 `code/pet_audios/`，命名 `<事件>_<序号>.wav|mp3`：

| 事件 | 文件名 | 触发时机 |
|---|---|---|
| 被摸 | `pet_touch_1.wav` … | 进入 `pet_touch` |
| 生气 | `scratch_1.wav` … | 进入 `scratch` |
| 惊醒 | `startled_1.wav` … | 进入 `startled` |
| 落地 | `landed_1.wav` … | 进入 `landed` |
| 猫叫（通用） | `meow_1.wav` … | 功能模块提醒时 |

**v2.0 的行为约定**：检测到 `pet_audios/` 为空 → 菜单里的「声音」项**置灰不可点**，鼠标悬停提示"未检测到音频素材"。有素材则默认开启，可手动关。

## 5. 菜单系统

### 5.1 三个入口

| 入口 | 触发方式 | 内容 |
|---|---|---|
| **A. 菜单栏图标** | 点击屏幕右上角的 PopoHere 图标 | 功能模块 + 设置模块 |
| **B. 右键桌宠** | 在猫身上右键 | 与 A **完全相同**的一套菜单 |
| **C. 状态面板** | A/B 里的「显示桌宠状态」 | 功能模块 + 设置模块 + **状态切换预览** |

A 和 B 共用一份菜单定义，避免两套逻辑跑偏。C 是一个独立的小浮窗，固定停在屏幕角落，可拖动、可关闭。

### 5.2 菜单结构

```
┌─ 功能 ────────────────────────────┐
│  🍅  番茄钟                 25:00 ▸ │
│  💧  喝水提醒                 开启 ▸ │
│  ✅  待办                   3 项 ▸ │
│  📊  系统状态                        │
├─ 设置 ────────────────────────────┤
│  显示 / 隐藏桌宠                     │
│  显示 / 隐藏桌宠状态                  │
│  大小            ▸ 160 / 220 / 300 / 380 │
│  声音            ▸ 开 / 关（无素材置灰）  │
│  暂停互动                           │
│  开机自启                           │
│  打开素材文件夹                       │
│  重置位置                           │
├──────────────────────────────────┤
│  关于 PopoHere                      │
│  GitHub 页面 ↗                      │
│  退出                               │
└──────────────────────────────────┘
```

**设置模块逐项说明**

| 菜单项 | 行为 | 是否持久化 |
|---|---|---|
| 显示 / 隐藏桌宠 | 隐藏窗口，菜单栏图标仍在 | ✅ |
| 显示 / 隐藏桌宠状态 | 开关状态面板（入口 C） | ✅ |
| 大小 | 四档：160 / 220 / 300 / 380 px | ✅ |
| 声音 | 开关音效；无音频素材时置灰 | ✅ |
| 暂停互动 | 猫继续动，但不响应点击/拖拽 | ✅ |
| 开机自启 | 写 `~/Library/LaunchAgents/com.popohere.pet.plist` | ✅（系统侧） |
| 打开素材文件夹 | Finder 打开 `code/pet_images/` | — |
| 重置位置 | 回到屏幕左下角默认位 | ✅ |
| 关于 PopoHere | 版本号、一句介绍 | — |
| GitHub 页面 | 浏览器打开仓库地址 | — |
| 退出 | 保存位置后退出 | — |

**状态面板（入口 C）**

一个 240×360 左右的小浮窗，固定贴在屏幕右下角（可拖动），内容：

```
┌──────────────────┐
│ PopoHere      ✕  │
├──────────────────┤
│ 状态预览           │
│  ○ 静息      idle  │
│  ○ 互动  pet_touch │
│  ○ 挠人    scratch │
│  ○ 自娱      play  │
│  ○ 睡觉     sleep  │
│  ○ 惊醒  startled  │
│  ○ 落地    landed  │
├──────────────────┤
│ 当前：idle  3.2s  │
└──────────────────┘
```

- 点状态名 → 猫立刻切到该状态（调试 + 演示两用）
- 底部实时显示当前状态和已停留时长
- **这个面板天然就是开发者要的调试面板**，v1.0 的 HTML 调试面板可以退休了

### 5.3 功能模块（4 个）

选型标准：**纯本地、零网络、单文件可实现、不抢焦点**。

| # | 模块 | 目录 | 做什么 | 猫怎么参与 |
|---|---|---|---|---|
| 1 | **番茄钟** | `core/func_pomodoro/` | 25 分钟专注 / 5 分钟休息循环，支持暂停、跳过 | 专注结束 → 猫走过来 + 气泡 `🍅 该休息了` + 可选音效 |
| 2 | **喝水提醒** | `core/func_hydration/` | 每隔 N 分钟（默认 45）提醒一次，可设工作时间段 | 气泡 `💧` + 猫抬头看你 |
| 3 | **待办清单** | `core/func_todo/` | 极简 todo，存本地 JSON，菜单里显示未完成数量 | 全部完成 → 猫 `✨` 庆祝一下 |
| 4 | **系统状态** | `core/func_sysmon/` | 在状态面板里显示 CPU / 内存 / 电量 | 不用猫参与，纯信息 |

**预留但 v2.0 不做**：迷宫小游戏（`core/func_maze/`）。目录规范已经能容纳它，届时新增一个 `func_maze` + 菜单项即可，核心代码不用动。

## 6. 技术实现要点

### 6.1 沿用现有技术栈

不改。Objective-C 外壳 + WKWebView + JS 状态机，构建链 `code/build/`。
新增的菜单和面板有两种落地方式：

| 方案 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| **A. 原生 NSMenu + NSPanel** | 系统感强、响应快、无障碍支持好 | 样式受系统限制 | ✅ **推荐**：主菜单走原生 |
| B. HTML 面板 | 样式自由、和猫同一套渲染 | 需要处理窗口焦点/层级，容易"不像 mac 应用" | 状态面板可以用，因为内容是列表 |

建议：**主菜单用原生 NSMenu**（菜单栏 + 右键都弹它），**状态面板用 NSPanel + 简单视图**。这样最稳，也最像原生应用。

### 6.2 代码落位

```
code/core/
├── func_state/        状态机（改造：合并 pet_head/pet_paw、walk→play）
├── func_render/       渲染（新增：按状态随机抽图已在状态机里）
├── func_input/        输入（简化：单一 body 命中区）
├── func_menu/         菜单（重写：原生菜单桥 + 状态面板）
├── func_pomodoro/     ★ 新增
├── func_hydration/    ★ 新增
├── func_todo/         ★ 新增
├── func_sysmon/       ★ 新增
└── func_window/       外壳（新增：NSMenu 构建、LaunchAgents 开机自启）
```

每个 `func_xxx` 对外只暴露 `init(ctx)` / `destroy()`，由 `main` 统一装配。**加功能不改别人的文件**。

### 6.3 新增脚本

| 脚本 | 作用 |
|---|---|
| `code/prepare/build_theme.py` | 扫描 `pet_images/` 的文件名，**自动生成 `theme.json`**。用户不再需要手写 JSON |
| `code/prepare/check_assets.py` | 校验素材完整性：缺哪个状态、某个状态只有 1 张、文件名不合规 → 列清单 |

### 6.4 兼容与迁移

- v1.0 的素材文件名（`idle.png`、`pet_head.png`…）→ v2.0 需要重命名为新规范。`build_theme.py` 会对旧名字给出提示
- `theme.json` 结构基本不变，只是 `states` 的 key 集合变了，`hitBoxes` 从两个变一个
- **旧版本不保留兼容**：v2.0 是一次干净的重构，用户重新跑一次预处理即可

## 7. v2.0 明确不做

| 不做 | 原因 |
|---|---|
| 迷宫小游戏 | 预留目录，下个版本做 |
| 任何网络请求（天气、AI 对话等） | 违反"纯本地"约束 |
| 窗口物理走动（猫走到屏幕别处） | 需要全局坐标控制，且会挡住用户操作 |
| 点击穿透 | 右键菜单需要整个窗口收事件 |
| Windows / Linux 适配 | 原生外壳是 macOS 专用 |
| Apple 公证 | $99/年，个人项目不值 |
| 多只宠物同屏 | 复杂度爆炸，收益低 |
| 语音合成 | 只播素材里已有的音频，不做 TTS |
