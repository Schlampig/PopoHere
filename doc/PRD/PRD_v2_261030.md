## 0. 这一版要解决什么

v1.0 已经能跑：一只透明浮窗里的猫，会呼吸、溜达、睡觉、被摸、炸毛、被抱起。但它有两个结构性问题：

1. **状态划分太碎，而每个状态只有一张图。** 10 个状态、10 张图，摸头/摸脚/挠人三张还是同一个文件。结果是"状态很多，但看起来都一样"。
2. **没有功能菜单。** 只有一个四条目的临时右键菜单，桌宠除了可爱之外不提供任何实用价值。

v2.0 的方向是反过来的：**状态收窄、每个状态喂饱素材**，再加一套真正能用、也好看的菜单系统。

## 1. v1.0 实际交付 vs 原 PRD 的差异

这一节是给评审用的：先说清楚上一版偏离了原设计哪些地方，免得 v2.0 建立在错误的假设上。

### 1.1 被推翻的决定

| 项 | 原 PRD（v1.0） | 实际实现 | 原因 |
|---|---|---|---|
| **技术栈** | Python 3.11 + PySide6 | **Objective-C (AppKit) + WKWebView** | PySide6 的依赖树过大，在受限的构建环境中无法安装；Swift 工具链也不可用。`clang + Objective-C + WebKit` 是当场唯一能编译、零依赖的方案 |
| **打包** | `pyside6-deploy` / PyInstaller | `clang` 直接产出通用二进制 `.app` | 没有 Python 运行时，包体从预计 50–85MB 降到 **768KB**，启动 <0.5s |
| **配置存储** | `theme.json` + `config.json` | `theme.json` + **NSUserDefaults** | macOS 原生偏好存储，不需要自建文件 |
| **动画** | `QTimer` 驱动 `QPixmap` 帧切换 | CSS 动画（`motion` 字段） | 每状态只有 1 张图，帧切换无从谈起；改用轻微形变给静态图生命感 |
| **气泡** | PNG 素材（`bubble_zzz.png`…） | **emoji 字符串** | 省掉一整套气泡素材，且可随时改文案 |

### 1.2 实现时才发现的偏差

| 项 | 原 PRD | 实际 | 说明 |
|---|---|---|---|
| **hitBox 坐标原点** | 左下角（`y` 从底部算） | **左上角** | 实现走 DOM 坐标，左上更直观。实际值也不同（`head y=0.02` / `paw y=0.52`） |
| **新增字段 `motion`** | 无 | `none/breathe/breathe-slow/bob-walk/shake/float/drop` | 用 CSS keyframes 表达呼吸、走动晃动、受惊抖动、落地回弹 |
| **拖拽实现** | Qt 窗口跟随鼠标 | `NSEvent` 本地监视器 + 屏幕坐标同步 | 用 `clientX` + 逐帧 `postMessage` 会形成坐标反馈环，导致剧烈抖动。这是 v1.0 修的最后一个大 bug |
| **菜单栏** | 显示/隐藏、暂停、打开主题、退出 | 去掉了暂停，多加了**大小分档**（160/220/300/380） | 暂停对桌宠意义不大，还容易和面板状态不同步 |
| **右键菜单** | 功能菜单（进入 `menu` 状态） | 只有 5 条临时项 | v2.0 才正式做 |
| **`sleep` 计时** | 窗口内按下/拖拽重置 | 状态机 `idle` 计时满 5s 分流 | 任何状态变化都会重置 `elapsed`，效果等价 |

### 1.3 完成度盘点

| 原 PRD 要求 | 状态 |
|---|---|
| 9 必需状态 + `landed` 可选 | ✅ 10 个全部实现 |
| 单击 <5px / <300ms、拖拽 ≥5px 判定 | ✅ |
| `startled` 仅在 `sleep` 被唤醒时触发 | ✅ 并有回归测试 |
| `menu` 状态 2 秒兜底 | ✅ |
| `pet_paw` → `scratch` 概率 + 冷却 + 连续摸脚 | ✅ 并修掉"第一次摸脚就自触发"的 bug |
| 空白区不作响应，仅留钩子 | ✅ `onBlankClick` |
| 素材经 `theme.json` 解耦 | ✅（但素材本身重复） |
| 完全无声、无音频库 | ✅ |
| 不做全局鼠标监听 | ✅ |
| Gatekeeper 说明 + 免公证分发 | ✅ README/使用说明都写了 |
| **小游戏预留** | ✅ 空钩子 |
| **多帧素材** | ❌ 每状态仅 1 张，源文件还有 3 组重复 |

## 2. v2.0 设计原则

1. **状态宁少勿多，素材宁多勿少。** 10 个状态各 1 张，不如 7 个状态各 4 张。
2. **一个状态 = 一种情绪，不是一个动作部位。** 摸头和摸脚对猫来说都是"被撸"，合并。
3. **转换要有因果，不能纯随机。** 静息→睡觉/自己玩是概率；撸它十次必然翻脸。
4. **素材命名即契约。** 用户只按 `<状态>_<序号>.png` 丢图，不写 JSON。
5. **功能模块插件化。** 每个功能一个 `func_xxx`，加功能不改核心。
6. **界面要配得上这只猫。** 不是系统默认控件的堆砌，也不做花哨的彩色卡片——深灰玻璃、圆角、留白，像 Popo 的毛色一样克制。

## 3. 状态机 v2.0

### 3.1 状态总表（7 个常规 + 2 个过渡）

| # | 状态 ID | 中文名 | 类型 | 时长 | 动效 | 气泡 |
|---|---|---|---|---|---|---|
| 1 | `idle` | 静息 | 常规 | 持续 | `breathe` | — |
| 2 | `touch` | 被撸 | 常规 | 1.5s | `none` | 随机 `❤️`/`😌`/`✨` |
| 3 | `scratch` | 挠人 | 常规 | 1.5s | `shake` | `💢` |
| 4 | `play` | 自娱自乐 | 常规 | 2.5s | `bob-walk` | — |
| 5 | `sleep` | 睡觉 | 常规 | 持续 | `breathe-slow` | `💤` |
| 6 | `dragging` | 被抱起 | 模态 | 持续 | `none` | — |
| 7 | `menu` | 待命（菜单中） | 模态 | 菜单关闭 | `none` | — |
| 8 | `startled` | 惊醒 | 过渡 | 1.0s | `shake` | `❗` |
| 9 | `landed` | 落地 | 过渡 | 0.8s | `drop` | — |

**相对 v1.0 的变化**

| v1.0 | v2.0 | 说明 |
|---|---|---|
| `pet_head` + `pet_paw` | → **`touch`** | 两个状态合并为一个"被撸"状态 |
| `walk` | → **`play`** | 语义从"走动"扩大到"自己找事做"（走路/舔毛/伸懒腰/追尾巴都由素材表达） |
| 其余 7 个 | 保留 | — |

净效果：**10 → 7 个常规状态**，同时每个状态可容纳多张素材。

### 3.2 交互简化

v1.0 用 `head` / `paw` 两个 hitbox 区分摸头摸脚。v2.0 **合并为一个 `body` 区域**：

- 整只猫就是一个命中区，点哪儿都是"撸它"
- 具体给出哪种反应，由 `touch` 的素材池随机决定
- hitbox 简化后，躺姿/坐姿共用一套，不再有偏移问题（v1.0 遗留短板 #3 顺手解决）

> 后路：以后若想让"摸头"和"摸脚"反应不同，按 `touch_head_1.png` / `touch_paw_1.png` 命名即可扩展，不需要改状态机。v2.0 不实现。

### 3.3 转换规则

```
                    ┌──────────── 单击 ────────────┐
                    │                              ▼
   ┌────────┐   5s   ┌──────┐                ┌───────┐
   │  idle  │───────▶│ play │                │ touch │
   └────────┘  35%   └──────┘                └───────┘
      │  │              │                          │
      │  │ 65%          │ 播完                      │ 连撸 10 次
      │  ▼              ▼                          ▼
      │ ┌───────┐    ┌──────┐                ┌─────────┐
      │ │ sleep │    │ idle │                │ scratch │
      │ └───────┘    └──────┘                └─────────┘
      │     │ 点击/拖拽                            │ 播完
      │     ▼                                      ▼
      │ ┌──────────┐                            ┌──────┐
      │ │ startled │                            │ idle │
      │ └──────────┘                            └──────┘
      │     │ 播完
      │     ▼
      │  idle / dragging（手还按着）
      │
      └── 拖拽 ──▶ dragging ── 释放 ──▶ landed ──▶ idle

   任意状态 ── 右键 ──▶ menu ── 点猫/关面板/兜底超时 ──▶ idle

   所有「播完」出口都走 _rest()：菜单面板还开着 → menu，否则 idle
```

**完整转换表**

| 当前状态 | 事件 | 目标 | 条件 |
|---|---|---|---|
| `idle` | 停留满 `idle_duration_sec` | `play` | 概率 `idle_to_play_probability`（默认 0.35） |
| `idle` | 同上 | `sleep` | 其余概率（默认 0.65，**睡觉概率更高，符合猫性**） |
| `idle` | 单击 | `touch` | 计入连撸 |
| `idle` | 拖拽 ≥ `click_max_drift_px` | `dragging` | — |
| `touch` | 单击 | `touch`（重播） | 连撸 +1；**达到阈值时当场转 `scratch`，不等播完** |
| `touch` | 播完 | `idle` / `menu` | 见下方「统一出口」 |
| `touch` | 拖拽 | `dragging` | 立刻打断 |
| `scratch` | 播完 | `idle` / `menu` | 进入冷却 `scratch_cooldown_sec`（默认 6s），`touch_streak` 清零 |
| `play` | 播完 | `idle` / `menu` | — |
| `play` | 单击 | `idle` | 打断，**不**触发 `touch` |
| `sleep` | 单击 / 拖拽 | `startled` | 唯一入口 |
| `startled` | 单击 | `touch` | 惊醒瞬间继续点也要计数，否则一轮猛点被动画吃掉 |
| `startled` | 播完 | `dragging` / `idle`·`menu` | 手还按着 / 否则 |
| `dragging` | 释放 | `landed` | 有 `landed` 素材 |
| `dragging` | 释放 | `idle` / `menu` | 无素材 |
| `landed` | 单击 | `touch` | 落地动画期间继续点也计数 |
| `landed` | 播完 | `idle` / `menu` | — |
| `menu` | 点猫 / 面板关闭 / `menu_timeout_sec` 兜底 | `idle` | 兜底超时同时清掉「菜单开着」标记 |
| 任意 | 右键 | `menu` | `dragging` 状态除外 |
| 预览中 | 播完（有 duration 按 duration，没有则 `preview_duration_sec`） | `menu` / `idle` | 见下方「统一出口」 |

**统一出口：`_rest()`**

除 `menu` 之外的每个"播完"都不直接写 `idle`，而是走同一个出口：

```
菜单面板此刻真的开着 ？ → menu ： idle
```

这条不变量保证 **「menu 状态 ⟺ 右键菜单面板」同时存在、同时消失**。状态机不猜，只认外壳写入的
`menu_open`（由面板 `show` / `hide` 回调更新）。状态面板里点状态名是**预览**：只演一遍，
不写连撸计数，演完同样走 `_rest()`。

**`touch_streak` 算法**

在**进入** `touch` 的那一刻计算，不在结束时算（v1.0 在这里踩过坑）：

```
if 上次进入 touch 距今 ≤ touch_repeat_window_sec:
    touch_streak += 1
else:
    touch_streak = 1
```

- 冷却期内（`scratch` 结束后 6 秒）`touch_streak` 保持 0，摸它只会 `touch`
- 阈值默认 **10**：撸十下才翻脸。按每次 1.5s + 4s 窗口算，大约是**连续撸 15–20 秒**
- 中途走开超过 4 秒，计数自然清零——符合"撸烦了"而不是"累计记仇"的直觉
- 这条规则是**确定性**的，不是概率：用户"一直撸就会生气"的预期必须可靠复现

### 3.4 行为参数（`theme.json → behavior`）

| 参数 | 默认 | 说明 |
|---|---|---|
| `idle_duration_sec` | 5 | 静息多久后自己找事做 |
| `idle_to_play_probability` | 0.35 | 分流去 `play` 的概率，其余去 `sleep` |
| `touch_repeat_window_sec` | 4 | 连击判定窗口 |
| `touch_scratch_threshold` | **10** | 几次连击后翻脸 |
| `scratch_cooldown_sec` | 6 | 挠完多久内不记仇 |
| `click_max_drift_px` | **12** | 位移小于它算单击；与外壳 `kDragThreshold` 必须一致 |
| `click_max_duration_ms` | 300 | 时长小于它算单击 |
| `menu_timeout_sec` | **120** | 菜单兜底超时。菜单开着时猫不该自己睡，这里只防"面板没关成功" |
| `preview_duration_sec` | 6 | 状态面板预览：没有 `duration` 的状态（`sleep`）演多久 |

> `click_max_drift_px` 从 5 调到 12 是实测结论：连点时手抖 6–10px 很常见，5px 会把每一下都
> 判成拖拽（窗口还会跟着跳），于是 `dragging → landed → idle` 循环，连撸计数永远是 0。

## 4. 素材规范与清单

### 4.1 命名规则

```
<状态>_<序号>.png     序号从 1 开始，等宽无前导零
```

- 一个状态只有一张时可省略序号（`idle.png`），**但推荐统一带序号**，以后加图不用改名
- 同一状态的素材在进入状态时**等概率随机抽一张并锁定**，状态持续期间不再变
- 建议构图：同一状态的多张图尽量**同一个机位、同一条地面基线**，否则切换时会跳

### 4.2 状态素材清单

| 状态 | 张数 | 拍什么 | 文件名 |
|---|---|---|---|
| `idle` | **3–4** | 坐着/趴着的静态，表情略有差别（发呆、看你、微眯眼） | `idle_1.png` … `idle_4.png` |
| `touch` | **4–6** | 被撸的反应：眯眼享受、抬头蹭手、翻肚皮、尾巴甩、侧头 | `touch_1.png` … `touch_6.png` |
| `scratch` | **2–3** | 不高兴：哈气、抬爪、飞机耳、炸毛 | `scratch_1.png` … `scratch_3.png` |
| `play` | **4–6** | 自己找事：走路、舔毛、伸懒腰、追尾巴、抓空气 | `play_1.png` … `play_6.png` |
| `sleep` | **3–4** | 睡觉：蜷缩、侧躺、露肚皮、爪子盖脸 | `sleep_1.png` … `sleep_4.png` |
| `dragging` | **2** | 被拎起来：四脚悬空、乱蹬 | `dragging_1.png`、`dragging_2.png` |
| `menu` | **1–2** | 端正坐好、看着你 | `menu_1.png`、`menu_2.png` |
| `startled` | **1–2** | 惊醒：猛地抬头、飞机耳 | `startled_1.png`、`startled_2.png` |
| `landed` | **1–2** | 落地：四脚着地瞬间、微微下蹲 | `landed_1.png`、`landed_2.png` |

**合计约 21–30 张。** 这是 v2.0 的核心工作量，也是这一版能不能"看起来丰富"的关键。

### 4.3 其他素材

| 用途 | 张数 | 文件名 | 规格 |
|---|---|---|---|
| **应用图标 / 面板 logo** | 1 | `logo_1.png` | 正方形，透明背景，512×512 或更大，主体占画面 70–85% |
| **菜单栏图标剪影** | 1 | `menubar_1.png` | **纯黑 + 透明**，正方形，建议 88×88（缩到 22pt 显示）。macOS 会当 template image 自动适配深/浅色菜单栏，**不要带颜色和阴影** |

缺失时降级：`menubar_1.png` 缺失 → 从 `menu_1.png` 自动抠剪影；`logo_1.png` 缺失 → 面板顶部只显示文字。

### 4.4 音频素材（v2.0 预留，可为空）

`code/pet_audios/`，命名 `<事件>_<序号>.wav|mp3`：`touch_1.wav`、`scratch_1.wav`、`startled_1.wav`、`landed_1.wav`、`meow_1.wav`（提醒用）。

`pet_audios/` 为空 → 菜单「声音」项**置灰**，悬停提示"未检测到音频素材"。

### 4.5 ⚠️ 必须写进「用户指南」的几条

这几条是给**所有自己动手做桌宠的人**看的，不是内部约定。v2.0 的 `README.md` / `doc/` / zip 内说明都要有：

1. **命名规则**：`<状态>_<序号>.png`，序号从 1 开始，同状态多张随机抽。
2. **背景请用纯色**（白墙、纯色地板、纯色布）。
   预处理用的是 **rembg/u2net 语义分割，不是大模型**：纯色背景质量最好、边缘最干净；花纹墙纸、复杂室内、多个物体同框时容易抠坏，而且没有"重试"按钮。这条写成建议而非硬性要求，但必须显眼。
3. **同一状态的多张图用同一个机位**，否则切换会跳。
4. 素材张数不足也能先跑起来（每个状态 1 张可用），**加图不用改代码，只改文件名**。

## 5. 菜单系统

### 5.1 三个入口

| 入口 | 触发方式 | 内容 |
|---|---|---|
| **A. 菜单栏图标** | 点击屏幕右上角的 PopoHere 图标 | 功能模块 + 设置模块 |
| **B. 右键桌宠** | 在猫身上右键 | 与 A **完全相同**的一套菜单 |
| **C. 状态面板** | A/B 里的「显示桌宠状态」 | 功能模块 + 设置模块 + **状态切换预览** |

A 与 B 共用一份菜单定义，避免两套逻辑跑偏。C 是独立小浮窗，可拖动、可关闭，默认停在屏幕右下角。

### 5.2 桌宠与状态面板的关系（评审结论）

**问题**：如果隐藏了桌宠，状态面板还开着，点面板里的状态名会怎样？猫会重现吗？

**结论：状态面板从属于桌宠，不能独立于桌宠存在。**

具体规则：

| 场景 | 行为 |
|---|---|
| 隐藏桌宠时，面板正开着 | 面板**一并自动收起**，但记住"它之前是开着的"这个意愿 |
| 桌宠隐藏期间打开菜单 | 「显示桌宠状态」**置灰**，悬停提示「桌宠已隐藏」 |
| 重新显示桌宠 | 若隐藏前面板是开着的，**自动恢复**；否则不弹 |
| 退出应用 | 面板开关状态持久化，下次启动按记录恢复 |

**为什么不选另外两种方案**：

- **"面板独立，点状态让猫重现"**：等于把面板变成隐藏的开关，用户点一下"静息"，猫突然出现——这是惊吓不是惊喜，而且和「显示桌宠」这个显式开关打架。
- **"面板独立，点状态无反应"**：会出现一个看得见、点不动的死控件，用户会以为应用坏了。

**从属模型**的好处是：任何时刻界面状态都能用一句话描述——「桌宠在，面板才可能开」。

**顺带的一致性问题**：桌宠隐藏时，定时提醒到点怎么办？
→ 提醒**不挂在桌宠身上**，而是屏幕右上角一个**独立的玻璃弹窗**（见 5.4）。桌宠藏起来、
没有音频、没有动画都不影响它。

### 5.6 功能模块（3 个）

选型标准：**纯本地、零网络、单文件可实现、不抢焦点**。

#### ① 定时提醒 `core/func_reminder/`

番茄钟、喝水、久坐本质都是"到点叫你一声"，合并为一个可配置的提醒器。
**「番茄钟」实际命名为「摸鱼」**，提醒文案是「摸鱼结束，接着干活~」——比"该专注了"更像人话。

- 默认预置 3 条规则，**默认全部关闭**：

| 预置 | 默认间隔 | 到点文案 |
|---|---|---|
| 摸鱼 | 25 分钟 | 摸鱼结束，接着干活~ |
| 喝水 | 45 分钟 | 到时间了，请去喝口水！ |
| 久坐拉伸 | 60 分钟 | 到时间了，请去拉伸一下！ |

- 每条可改：间隔（1–180 分钟，**1 → 5 → 10 → 15…** 按合法档位走）、启用开关、**一次 / 间隔** 模式
- **一次 / 间隔**：每行右侧一个两段开关
  - `一次`（**默认**）：响过一次就自动关闭，下次不再提醒
  - `间隔`：按设定的间隔循环，直到用户自己关掉
- **到点表现：屏幕右上角的独立弹窗**（`func_reminder/PHAlert`）

| 项 | 规格 |
|---|---|
| 位置 | 屏幕右上角，距右边/上边各 16px，`NSFloatingWindowLevel`，**不抢键盘焦点** |
| 外观 | 与右键菜单/状态面板同一套玻璃：`rgba(20,19,18,.62)` + `NSVisualEffectView` + 16px 圆角 + 猫眼绿点缀 |
| 文案 | `{message}（{n}s）`，每条自带整句（见表），不用模板硬拼，避免"请去番茄钟"这种别扭句子 |
| 倒计时 | 10 秒，每秒把括号里的秒数改一次；归零自动关闭 |
| 操作 | 文字下方一个「确认」按钮，点了立刻关闭；点确认和等超时都算"这一轮结束" |
| 多任务 | 同时到点**叠在同一个面板里**，每条各自倒计时、各自「确认」，先关哪条由用户决定；全关完面板才收起 |
| 独立性 | 桌宠被隐藏、没有音频素材、没有动画都不影响；**不再弹气泡**，也不再动菜单栏图标 |
| 结束之后 | 该项自动重新计时（`remaining = minutes × 60`），不需要用户做什么 |

- 菜单里直接显示每条的下次时间（如 `摸鱼 25 分钟`）
- "跳过本次"不重置周期（v2.0 未实现，见待确认项）

#### ② 待办清单 `core/func_checklist/`

- **checklist 形态**：一行一条，左侧复选框，勾掉即完成
- **上限 10 条**，每条 **≤50 个中文字**（超出截断并提示）
- 可新增、编辑、删除、勾选/取消勾选
- **一键清空**（需二次确认，避免误删）
- 全部勾完 → 猫做一次庆祝反应（`touch` + `✨` 气泡）
- 存本地 JSON（`~/Library/Application Support/PopoHere/checklist.json`）
- 菜单项右侧显示未完成数量

#### ③ 系统状态 `core/func_sysmon/`

- 在状态面板底部显示 CPU / 内存 / 电池
- 每 5 秒采样一次，开销可忽略
- 不参与桌宠状态，纯信息

**预留不做**：迷宫小游戏（`core/func_maze/`）。目录规范已能容纳，届时新增 `func_maze` + 菜单项，核心代码不用动。

## 6. 技术实现要点

### 6.1 沿用现有技术栈

不改。Objective-C 外壳 + WKWebView + JS 状态机，构建链 `code/build/`。

菜单与面板的落地方式：

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 原生 NSMenu + NSPanel | 系统感强、响应快、无障碍好 | 样式受系统限制，做不出玻璃质感 | 仅用于**菜单栏图标下拉**（macOS 惯例就是原生菜单） |
| **HTML/CSS 面板（透明无边框窗口）** | 玻璃质感、圆角、配色完全可控 | 需自己处理失焦收起、阴影 | ✅ **右键菜单与状态面板走这条** |

**决定**：菜单栏图标点开用原生 `NSMenu`（符合系统预期）；右键桌宠、状态面板用 **CSS 实现的独立透明窗口**，这样才有第 7 章那套视觉。

### 6.2 代码落位

```
code/core/
├── func_state/        状态机（改造：合并 pet_head/pet_paw → touch，walk → play）
├── func_render/       渲染
├── func_input/        输入（简化：单一 body 命中区）
├── func_menu/         菜单（重写：面板窗口 + 菜单定义）
├── func_reminder/     ★ 新增：定时提醒
├── func_checklist/    ★ 新增：待办清单
├── func_sysmon/       ★ 新增：系统状态
└── func_window/       外壳（新增：面板窗口、LaunchAgents、系统通知）
```

每个 `func_xxx` 对外只暴露 `init(ctx)` / `destroy()`，由 `main` 统一装配。**加功能不改别人的文件**。

### 6.3 新增脚本

| 脚本 | 作用 |
|---|---|
| `code/prepare/build_theme.py` | 扫描 `pet_images/` 文件名，**自动生成 `theme.json`**，用户不写 JSON |
| `code/prepare/check_assets.py` | 校验素材：缺哪个状态、某状态只有 1 张、命名不合规 → 列清单 |

## 7. 视觉设计规范

### 7.1 设计语言

> **深灰玻璃 + 圆角 + 一点猫眼绿。**

参照 Popo 本人的毛色：主体黑灰，眼睛暗绿。界面不抢猫的戏，只做一层克制的、有质感的浮层。

- **材质**：半透明深色玻璃（backdrop-filter），能看到桌面的模糊色彩，但文字始终清晰
- **形状**：面板 16px 圆角，条目 9px 圆角；不用方角、不用胶囊
- **色彩**：只用无彩色 + 一个绿点缀；不加第二个强调色
- **密度**：条目高 30px，组间距 6px，面板内边距 10px——接近 macOS 原生菜单的呼吸感

### 7.2 设计变量

| Token | 值 | 用途 |
|---|---|---|
| `--panel-bg` | `rgba(24, 23, 22, 0.74)` | 面板底色 |
| `--panel-blur` | `blur(30px) saturate(180%)` | 背景模糊 |
| `--panel-border` | `1px solid rgba(255,255,255,0.09)` | 外描边 |
| `--panel-inner` | `inset 0 1px 0 rgba(255,255,255,0.06)` | 顶部高光，让玻璃"有厚度" |
| `--panel-shadow` | `0 18px 48px rgba(0,0,0,0.42)` | 投影 |
| `--radius-panel` | `16px` | 面板 |
| `--radius-item` | `9px` | 悬停/选中条目 |
| `--text-1` | `rgba(255,255,255,0.94)` | 主文字 |
| `--text-2` | `rgba(255,255,255,0.52)` | 次要文字、快捷键、版本号 |
| `--accent` | `#8FAE9B`（猫眼绿） | 选中态、开关打开、勾选框 |
| `--danger` | `#D97A6C` | 清空、退出等破坏性操作 |
| `--row-h` | `30px` | 菜单行高 |

**字体**：`-apple-system, "PingFang SC"`；菜单项 13px / 行高 1.4；分组标题 11px、字重 600、`letter-spacing: 0.04em`、灰色；数字用 `font-variant-numeric: tabular-nums`（倒计时不跳动）。

### 7.3 交互与动效

| 场景 | 规格 |
|---|---|
| 面板弹出 | `scale(0.96) → 1` + `opacity 0 → 1`，160ms `cubic-bezier(.2,.8,.2,1)` |
| 面板收起 | 120ms，只淡出（收起比弹出快） |
| 条目悬停 | 背景 `rgba(255,255,255,0.07)`，90ms |
| 条目按下 | 背景 `rgba(255,255,255,0.12)` |
| 子菜单 | 向右展开，与父项顶部对齐，150ms |
| 勾选框打钩 | 描边路径动画 200ms |

**必须遵守**：
- 系统开启「降低透明度」时，`--panel-bg` 退化为 `rgba(28,27,26,0.97)`、去掉 blur（可读性优先）
- 系统开启「减弱动态效果」时，所有位移/缩放取消，只保留淡入淡出
- 面板文字对比度 ≥ 4.5:1（深灰底 + 94% 白字达标）
- 面板失焦自动收起（点击桌面别处）

### 7.4 状态面板的额外要求

状态面板比右键菜单"重"，因为它常驻：

- 顶部 1px 分隔线，下面是状态列表
- 当前状态用 `--accent` 实心圆点标记，其余空心圆
- 底部"当前 idle · 3.2s"用 `--text-2` + 等宽数字
- 拖动面板：按住顶部标题栏拖动（和菜单"点一下就关"区分开）
